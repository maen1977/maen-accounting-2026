# Maen Accountings - إصلاحات السحابة والمصادقة v3

## ما الذي تغيّر

1. **إضافة تهيئة Firebase مباشرة من Flutter**
   - تمت إضافة الملف `lib/firebase_options.dart`.
   - التطبيق صار يهيّئ Firebase على Android مباشرة عبر `Firebase.initializeApp(options: ...)` بدل الاعتماد الكامل على الضبط الأصلي داخل المنصة.
   - هذا يقلل احتمال ظهور شاشة محلية فقط بسبب فشل تهيئة Firebase.

2. **منع الوصول غير الآمن إلى FirebaseAuth قبل التهيئة**
   - تم تعديل `AuthService` حتى لا يقرأ `FirebaseAuth.instance.currentUser` إذا لم تكن Firebase جاهزة.

3. **شاشة أوضح عند فشل السحابة**
   - إذا فشلت تهيئة Firebase، لن يظهر الأمر وكأن التطبيق يدعم الإيميل فقط بلا كلمة مرور.
   - ستظهر شاشة توضّح أن المشكلة في تهيئة Firebase نفسها.
   - تمت إضافة زر **إعادة فحص Firebase**.
   - تمت إبقاء **الوضع المحلي فقط** كخيار ثانوي واضح، وليس كبديل صامت.

4. **عدم الفتح المحلي الصامت عند فشل Firebase**
   - إذا كان هناك إيميل محفوظ محليًا لكن Firebase غير جاهزة، لن يدخل التطبيق مباشرة بشكل قد يربك المستخدم.
   - سيطلب منه اتخاذ قرار واضح: إعادة المحاولة أو المتابعة محليًا.

5. **تشخيص سحابي داخل الإعدادات**
   تمت إضافة معلومات مباشرة داخل صفحة الإعدادات:
   - جاهزية Firebase
   - حالة جلسة Firebase
   - بريد Firebase الحالي
   - مسار المستند السحابي المتوقع
   - آخر خطأ Firebase
   - آخر خطأ سحابي
   - آخر نتيجة لاختبار الاتصال السحابي
   - زر **اختبار الاتصال السحابي**

## كيف تختبر بعد التعديل

1. شغّل التطبيق.
2. إذا ظهرت شاشة الإيميل وكلمة المرور:
   - أنشئ حسابًا أو سجّل دخولًا.
3. بعد الدخول:
   - افتح الإعدادات.
   - اضغط **اختبار الاتصال السحابي**.
4. داخل Firebase Console تأكد من وجود:
   - `Authentication > Users` وفيه المستخدم.
   - `Firestore Database > Data > profit_tracker_backups/<email>`

## إذا لم تعمل السحابة بعد

افحص بالترتيب:
- هل ظهر المستخدم فعلًا في `Authentication > Users`؟
- هل قواعد Firestore منشورة؟
- هل المستند يُنشأ داخل `profit_tracker_backups`؟
- هل بريد Firebase الحالي داخل الإعدادات يطابق بريد الحساب داخل التطبيق؟
